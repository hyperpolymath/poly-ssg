= Poly SSG: preserve the useful work and retire the original cleanly
:revdate: 2026-11-04
:toc:
:toclevels: 2

*Status: proposed component dispositions, prepared for Poly SSG PR #3.*
This plan records a finite route to retirement. The independent Git tree
comparison is recorded in `PRESERVATION.adoc`: the original `poly-ssg/` subtree
and the extracted root both identify tree
`6a8aa93222c8261c3e81b37acd7d1bd59f42bdc4`. That establishes source-tree
correspondence, including file modes; it does not report an archive, release,
working replacement, or completed runtime qualification. The preservation gate
checks the imported commit's tree identity, ancestry and object connectivity.

== Intended outcome

Retain the original Git history and useful experiments in an identified source
snapshot; publish useful, original educational and discovery material in
`stuff-of-awe/awesome-ssgs`; assign any selected runtime work to a maintained
successor; and explicitly discontinue the remaining experiments. Close the
retirement work when those decisions and their evidence are recorded.

There is no requirement to finish every proposed generator, implement every
historical feature, or make every archived experiment build. A functioning
successor needs execution evidence. A discontinued experiment needs preserved
source, an honest status, and removal of any claim that a live consumer can
depend on it. These are different outcomes and should be recorded separately.

The proposed end state uses GitHub archival, with history and a clear successor
notice retained. Repository deletion is outside this plan. Retirement of Poly
SSG and archival of its parent Polystack are separate repository decisions;
the SSG work alone cannot establish that every other Polystack domain is ready.

== Three claims, with separate evidence

[cols="2,4,3",options="header"]
|===
|Claim |Minimum evidence |What the claim establishes
|Verified preserved snapshot
|Original commit and prefix; extracted commit; matching Git tree identity or
an explicit file/mode/blob comparison; extraction method; retained authorship
and history; recorded licences and any unresolved notices; a durable ref.
|The material can be recovered with its provenance. It establishes no runtime
or integration guarantee.
|Working successor
|Named repository and exact commit; supported operations; pinned toolchain;
executed input-to-output tests; negative cases; output inspection; applicable
reviews and real CI; consumer ownership and documented limitations.
|Only the tested functions and environments have a working replacement.
|Deliberately discontinued function or experiment
|Explicit disposition and rationale; preserved source ref; dependency and
consumer review; corrected availability/status documentation; any live caller
receives a clear unsupported/unavailable result rather than an implied service.
|The function has been retired intentionally. No implementation is promised
merely to close the preservation task.
|===

Every source area receives a preservation state and an operational disposition.
Public curation is an additional decision. For example, an experiment may be
fully preserved, deliberately discontinued, and still useful in a historical
learning section.

== Public curation and private preservation

`stuff-of-awe/awesome-ssgs` already supplies the intended public home. Its scope
is useful discovery, comparative evidence, unusual-language research and honest
maturity labels. It has a curation gate, not an SSG runtime qualification gate.

Recommended bounded addition:

. Add `docs/COMPARISON-NOTES.md`, with original guidance on comparing the same
  publishing task across implementations and recording reproducible results.
. Link it from the existing "Compare generators usefully" section.
. Retain the existing starter status and distinction between inspected source,
  executable examples and verified integrations.
. Update the public source map only when the underlying disposition changes.
  Use public tracker #165 for public migration status; keep private source URLs,
  source excerpts, environment details and private review discussion out of the
  public article.
. Run the existing local catalogue validator and tests. A passing curation gate
  establishes link/notice/status checks within its stated scope; it does not
  verify the linked generators.

The destination contribution policy and validator were inspected. Every public
Markdown document needs the CC-BY-SA-4.0 marker. Local links must resolve inside
the repository, and the validator rejects private Polystack/Poly SSG source
URLs. Third-party code must remain in its appropriately licensed source home.

=== 3. Record a finite component decision ledger

For each source-area row, record: preservation receipt; proposed canonical

Prioritise live consumers and unique executable source/tests. Select only work
that is useful enough to maintain. Unselected material can be closed as a

Update qualification #2 and public tracker #165 to reflect the adopted scope.

Replace active-status claims with an accurate retirement notice, canonical

Reconcile open issues and PRs: completed preservation, superseded work,

Once the scoped retirement decision is recorded and live dependencies are

intended destinations. Record these observations in a final closure receipt.

== Completion criteria

* The exact source snapshot and provenance are verified and recoverable.
* The repaired documentation/workflow PR has real passing checks at its final
  head and an observed merge result.
* Each broad source area is assigned a destination or preserved historical
  disposition; no unique source is discarded because a similarly named repo exists.
* Public curation retains useful explanations with accurate status and licence
  notices, without exposing private source material.
* Each actual consumer has a working successor or a recorded, explicit
  unavailability/discontinuation decision.
* Open runtime promises remain tracked honestly; discontinued experiments do
  not require new implementations to permit preservation closure.
* The exact repository being retired, its archival result and stopped obsolete
  automation are recorded separately from preservation and runtime testing.
