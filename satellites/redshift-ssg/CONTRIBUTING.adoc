=== Getting Started

==== Prerequisites

* Git
* Deno (for running adapters)
* Node.js (optional, for npm ecosystem tools)

==== Setup

[source,bash]
----
# Clone the repository
git clone https://github.com/hyperpolymath/shift-ssg.git
cd shift-ssg

# Using Nix (recommended for reproducibility)
nix develop

# Or using toolbox/distrobox
toolbox create shift-ssg-dev
toolbox enter shift-ssg-dev
# Install dependencies manually

# Verify setup
just check   # or: cargo check / mix compile / etc.
just test    # Run test suite
----

=== How to Contribute

==== Reporting Bugs

*Before reporting*: 1. Search existing issues 2. Check if it’s already
fixed in `+main+` 3. Determine which component the bug affects

*When reporting*:

Use the link:.github/ISSUE_TEMPLATE/bug_report.md[bug report template]
and include:

* Clear, descriptive title
* Environment details (OS, versions, toolchain)
* Steps to reproduce
* Expected vs actual behaviour
* Logs, screenshots, or minimal reproduction

==== Suggesting Features

*Before suggesting*: 1. Search existing issues and discussions 2.
Consider how the feature fits with the project

*When suggesting*:

Use the link:.github/ISSUE_TEMPLATE/feature_request.md[feature request
template] and include:

* Problem statement (what pain point does this solve?)
* Proposed solution
* Alternatives considered

==== Your First Contribution

Look for issues labelled:

* https://github.com/hyperpolymath/shift-ssg/labels/good%20first%20issue[`+good first issue+`]
— Simple tasks
* https://github.com/hyperpolymath/shift-ssg/labels/help%20wanted[`+help wanted+`]
— Community help needed
* https://github.com/hyperpolymath/shift-ssg/labels/documentation[`+documentation+`]
— Docs improvements

=== Development Workflow

==== Branch Naming

....
docs/short-description       # Documentation
test/what-added              # Test additions
feat/short-description       # New features
fix/issue-number-description # Bug fixes
refactor/what-changed        # Code improvements
security/what-fixed          # Security fixes
....

==== Commit Messages

We follow https://www.conventionalcommits.org/[Conventional Commits]:

....
<type>(<scope>): <description>

[optional body]

[optional footer]
....

*Types*: `+feat+`, `+fix+`, `+docs+`, `+style+`, `+refactor+`, `+test+`,
`+chore+`, `+security+`

==== Pull Request Process

[arabic]
. Fork the repository
. Create your feature branch (`+git checkout -b feat/amazing-feature+`)
. Make your changes
. Ensure tests pass
. Commit your changes using conventional commits
. Push to your branch (`+git push origin feat/amazing-feature+`)
. Open a Pull Request
